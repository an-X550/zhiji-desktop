# 知己桌面端核心体验：需求复核与收敛方案

日期：2026-09-09。状态：已实施（含 J14/J16 扩展补充）；本版替代此前同名方案的交互与范围要求。
目标：`C:/Users/panda/.claude/skills/知己/apps/zhiji-desktop`。本轮以 2.6.12 为基线，实施结果为 2.6.13；审查和验收均针对工作区与本地 packaged-asar，不代表安装版。

## 1. 第一性原理结论

真实目标只有三个：顺畅记录、按需获得反馈、以后找得到。用户不应该理解生成管线、记录版本、页面内部状态，也不应该为了程序复用多走一步。

用户已提供的真实证据：历史日志不能直接分析；0 字页面仍发起调用；反馈难读且找不到；短日志也要内部滚动；明确要求同日反馈覆盖、同日日志有提示。这些是本轮需求依据。

代码补充证据：保存失败未退出生成状态；保存响应无条件覆盖编辑器；旧错误重试不保存新正文。这些是核心流程的可靠性缺陷，值得一并修复，但不宣称用户已实际遭遇。

尚未证实：用户需要日志自动合并、内容级去重、多版本管理、完整诊断面板、全局数据加载重构。这些不应变成必做任务。模拟产品经理和用户只能检查合理性，不能替代真实使用验证；不声称已证明所有用户都会使用本设计。

## 2. 对上一版方案的纠偏

| 原方案要求 | 问题 | 本版决定 |
|---|---|---|
| 历史日志必须进入编辑器再生成 | 用户只是想读完后分析，无需编辑；为复用代码增加步骤 | 删除小字生成入口，将动作放进固定“日反馈”区域；直接调用共用生成函数，不强迫编辑 |
| 生成完成自动跳到过去日志 | 用户可能已换到其他日期或继续记录，自动跳页会打断 | 当前仍在该日期且无新修改时，可切到同一工作区的反馈标签；否则仅提示完成，不抢导航或焦点 |
| 同日正文和项目相同就返回旧记录 | 内容相同不等于用户操作重复；会使明确“另记一条”失效 | 删除内容级自动去重。仅防一次保存操作的重复点击，成功后绑定原 ID，后续保存更新它 |
| 所有 J1–J18 都往执行任务里放 | 混合核心痛点、推断风险和旁支优化，范围膨胀 | 明确本轮必做、关联小修、暂缓三类；候选问题不是隐式实施授权 |
| 生成任务期间锁定编辑字段 | AI 可能耗时较长，不能让用户等着才能继续写 | 仅短暂本地保存阶段可锁字段；AI 阶段允许继续写，新增修改保留、反馈标待更新 |
| 根据任意模板标题判断“没有内容” | 合法短句可能被拦，变成新限制 | 空白本地拦截；只有能准确识别的未填写内置模板才按空内容处理，不新增语义分类 |
| 固定宽度、所有长文只有一种滚动方式 | 像素数不等于可用性；长文本场景可能不同 | 以短文可完整阅读、长文可访问、按钮不遮字为验收，样式参数为试验起点 |
| 旧数据清理要有新的用户重试流程 | 用户只想看反馈，不想管理存储清理 | 兼容处理在现有存储层完成，异常如实报告，不新增清理面板或让用户重新生成来修文件 |

“少一个入口”不应高于“少一次无意义跳转”。保留符合场景的按钮并共用逻辑，不等于维护两套业务。

## 3. 最小可用交互

### 写日志与阅读反馈

保留现有“写日志 / 过去日志”导航。在日志工作区使用共用的“日志 / 日反馈”内容区，反馈有独立排版，不在输入框下方游离展示，不新加一级侧栏页面。

- 今日和历史日期同样支持“保存日志”和“保存并生成反馈”；不自动分析、不改未来日期限制。
- 空编辑器提示“先写点内容，再保存或生成反馈”，禁用相应提交；即使当天已有日志，也不能隐式代用。用户主动打开已保存日志后，可以分析那份日期的材料，这是另一种明确操作。
- 未配置 AI 仍可保存、阅读已有反馈，提供配置入口即可。
- 查看反馈始终是读取，不调用模型。没有反馈时，反馈区显示“生成反馈”；日志已变时显示“更新反馈”；已有未变化反馈保留次级“重新生成”，旁注明成功后替换。
- 编辑器有未保存修改，发起生成必须先保存；保存失败就停止并保留草稿。失败后修改了正文，再试也必须分析最新保存内容。
- 生成成功仍停留在原日期、且没有新输入时，可以在当前工作区展示反馈；否则就地提示完成，用户自己打开。切标签不能清掉编辑器草稿，切日期不能带出其他日期的反馈或错误。
- 保存阶段使用简短状态；AI 阶段显示处理中并防重复生成。若复用现有取消能力成本很低则提供，取消不宣称服务商已免计费。
- 日反馈明确日期，同日多条时显示“根据这一天的 N 条日志生成”。来源内容变化只提示待更新，不自动花钱。

历史详情的“日反馈”标签是找回入口，替代原先很小的生成文字链接。没有反馈时在该区域直接生成，不要求用户编辑不需要修改的原文。两处展示共用同一组件/服务和持久化记录。“复盘 → 历史复盘”继续兼容，不另建存储。

### 同日已有日志

不把“发现同日已有内容”变成强制选择页。正常写作仍可开始，在日期附近用一条非阻断提示：

> 这一天已有 1 条日志。继续编辑已有日志，或另记一条。

一条时“继续编辑”打开该条；多条时“查看已有日志”定位该日列表供选择。已经输入的草稿保留，打开旧记录沿用未保存守卫；不自动替换正文。保存区用简短说明“将新增一条日志”，不为了不同状态不断换成长按钮名称。显式新建始终允许，不按正文相同拒绝。

成功新建后绑定返回的 ID，连续按保存更新同一条；提交中禁用重复点击并在处理函数挡住重入。无修改再次保存不改 updatedAt。若当前应用确有跨窗口重复提交，再用现有写入协调解决操作重入；不预先建内容查重服务。

同日已有多条原始日志不删除、不自动合并。一次日反馈汇总该日全部有效日志，延续现有语义。用户改日期时仅修改当前记录，不覆盖目标日已有记录；两日反馈的新鲜度自然重算。

### 同日只有一份反馈

这是用户明确要求，不是推测。再次生成成功后替换该日反馈，失败、取消或原子写失败保留原结果。查看旧结果不需要等待新生成成功；不增加版本选择、二次覆盖确认或每次生成的备份文件。

沿用该日反馈 ID/文件路径，更新正文、来源版本、模型和最近生成时间；无反馈才创建。使用既有任务与原子写机制防并发新增，核对实际日反馈写入口；不扩大为 Agent 内核重构。若需要生成时间字段，兼容旧数据，以既有时间回退。

旧数据已存在多份：读取阶段只选最新有效记录供正常列表展示；该日下次成功更新后，多余旧反馈移入现有回收站，不保留在有效存储。此兼容清理不动原始日志、不全库迁移。写新结果失败不清旧文件；清理失败不得说全部成功，也不得再调用模型来重试清理。旧链接缺失按现有提示处理，不新建别名系统。已生成周期复盘不自动重写。

### 阅读与空间

保留现有 textarea、MarkdownDocument 和主题。反馈在固定阅读容器内有标题、日期、段间距与适当行高；技术详情默认折叠。可先试 17–18px、1.75–1.9 行高，再根据实际屏幕调整，不作为硬性像素合约。

编辑器优先使用更多可用高度、随内容增长，避免短文在小框内滚动；收紧过大留白。长文可滚动，保存操作可达且不盖字。不要求所有文字无论多长都在首屏显示，不更换富文本框架。
