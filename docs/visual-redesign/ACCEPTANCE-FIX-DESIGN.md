# v2.6.10 界面验收与最小修正方案

日期：2026-09-09。状态：审阅与实施均已完成；实施结果见 [ACCEPTANCE-FIX-IMPLEMENTATION-RESULT.md](ACCEPTANCE-FIX-IMPLEMENTATION-RESULT.md)。本文件保留为 v2.6.10 问题诊断与最小修正依据。

范围：用户明确指定的 `apps/zhiji-desktop`。本文件在以下五项上取代旧 DESIGN.md 的方案；其他既有业务约束继续有效。

## 结论与证据边界

本轮不能判定视觉验收通过。用户实际运行的三张截图已显示历史列表与正文相互遮挡、暗色编辑器白色滚动条，以及首页全屏失衡。源码也存在相应约束缺口。IMPLEMENTATION-RESULT.md 中的测试和截图是上一轮执行记录，本轮没有重新运行完整测试或启动 Electron，不能把这些记录当成本轮验证结果。原生下拉展开状态由用户反馈，尚需在当前打包版本实际展开确认。

真正目标是让用户容易开始记录、找到旧记录，并在常用窗口尺寸和主题下看清内容。并不需要再次创造视觉风格。中性暗色是用户明确偏好；绿色暗底来自上一版设计方案，执行者并未偏离方案，本轮纠正的是设计选择。

## 五项修正

| 优先级 | 问题与依据 | 最小解决路径 |
| --- | --- | --- |

| P1 | 深绿色覆盖整个暗色工作区。暗色 bg/surface 为 `#1d2220/#252c28`，导航另有硬编码绿色背景。 | 换成中性灰黑底与灰色层次，绿色只用于主动作和少量状态；同时移除导航大面积绿色硬编码。 |
| P1 | 长模板出现白色滚动条；用户反馈下拉白底浅字。源码只修改 select 箭头，没有声明 color-scheme。 | 让实际解析后的主题驱动原生控件；必要时补 option 与 scrollbar 样式，优先保留原生 select。 |
| P2 | 写日志／过去日志入口小，工具栏项目与模板是 12px 文本。 | 同一位置放置两个清晰的模式按钮，放大命中范围；工具控件增加到常规桌面字号和高度。 |
| P2 | 首页全屏内容靠上且下方空白过多。`.start-page` 固定上限 720px、仅顶部内边距；截图符合该布局。 | 适度放宽内容，按可用高度调整整个内容组的位置；保留窄窗口表现，不新增占位卡片。 |

### 1. 历史页：解决可用宽度与内容宽度冲突

- 保留列表＋阅读器双栏；外层可采用 `minmax(0, .8fr) minmax(0, 1.2fr)`。在列表、按钮及按钮内文本容器补齐 `min-width: 0`，按钮列改为 `95px minmax(0, 1fr)`。
- 标题单行省略，摘要允许最多两行；时间不挤压成碎片。阅读器标题、长链接可断行；表格／代码块仅在自身横滚。
- 以历史内容容器可用宽度决定折叠；可复用 CSS container query。在内容不足约 720px 时单栏，最终阈值按实测调整。单纯针对窗口 980px 的断点无法表达侧栏和内边距占用。
- `.reader-meta`、`.reader-actions` 允许换行；不要为了保留一行而缩小编辑、删除按钮。
- 筛选条件在日志模式只有两项，现有三列和 nth-child 响应式规则不匹配。根据两项／三项显式设置布局，或采用能正确容纳两种状态的 auto-fit；搜索框优先占剩余空间。
- 用长中文标题、连续英文／URL、多个操作按钮验证根因。当前为源码支持的高置信诊断，实施时先采集边界数据再确认，不假称已经动态复现。

### 2. 暗色：中性底色与有限强调色

建议起点：bg `#202020`、surface `#292929`、surface-secondary `#242424`、fill `#333333`、fill-strong `#3d3d3d`；正文 `#eeeeee`、次要文字 `#bdbdbd`、辅助文字 `#a6a6a6`；分隔线 `#424242`。控件边框单独验证可辨识度，不把微弱分隔线用于输入控件边界。

同步检查 surface-glass、导航文字／hover／选中态，避免只换背景变量而残留绿色大片。保留已有可读的绿色主按钮、焦点和成功状态；不照搬 ChatGPT 品牌，不新增紫色或其他大面积色彩。浅色主题保持现有方向。

### 3. 原生控件：让浏览器知道当前主题

根元素按已解析主题设置 `color-scheme: light` 或 `dark`，不要仅依赖系统 prefers-color-scheme，否则手动切暗、系统仍浅时会继续出错。该属性影响原生表单控件和滚动条，见 [MDN color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme)。

先验证这一步；若当前 Electron/Windows 的弹出选项仍不清晰，再对 option/optgroup 设置明确的 surface/ink，并局部使用 scrollbar-color 或 Chromium 兼容样式。不要隐藏滚动条。原生弹出菜单受平台影响，CSS 声明成功不能代替展开菜单验收；若平台截图接口捕获不到原生 popup，记录实际人工展开结果，不用自制 DOM 菜单冒充证据。

保留模板“追加”语义。白色条不是模板正文故障，不改模板内容或保存逻辑。写作区保留一个主要正文滚动区域，避免 `.writing` 与 textarea 无必要的双重滚动。

### 4. 日志入口：更容易识别和点击

使用两个普通按钮组成紧凑模式切换：“写日志”“过去日志”。目标高度 36–40 CSS px、字号 14px、水平内边距 12–16px，有明确选中态和键盘焦点。通过既有切换 handler 保留未保存确认；不新建路由系统，也不引入需要额外键盘模型的 tab 组件库。

关联项目／日志模板保留当前工具行，将可点击 select 本体高度提高到至少 32px，优选 36px，字号 13–14px；不可只把外围 label 放大。长项目名收缩或省略，窄窗口自然换行。日期、字数等辅助信息不必全面放大。

### 5. 首页：改善内容组的比例，不填充屏幕

14 寸是物理尺寸，不能据此写专用断点；实际 CSS viewport 取决于分辨率、系统缩放和窗口。截图证明比例问题，但不能从图片像素反推准确 CSS viewport。

保留日期、主标题、建议下一步、三项快捷入口与本地状态。宽窗口将内容上限从 720px 调到约 840–900px；整个内容组在可用工作区垂直方向略高于中心。优先 flex/grid 布局的自动上下外边距或安全居中，确保内容高于可用空间时回到顶部并可滚动。不要 transform 位移、固定 top 百分比或放大整个应用。

主行动可增加适度内边距和轻表面分组，让它成为视觉中心；保持正文行长与标题字号，不把所有横线拉满大屏。窄／矮窗口保留紧凑排列，三项快捷入口按空间换行。验收以全屏截图中内容组是否均衡、按钮是否醒目为准；不以“消灭空白”作为目标。

## 取舍与停止条件

不新增 UI 依赖、首页统计、插画、动画、可拖动分栏或全页面重设计。共享暗色变量变化后只对其他页面做必要回归。本轮不顺带修改记录选择、AI、存储或业务状态机。

五项验收通过即结束。布局问题需要真实浏览器边界验证；Grid 自动最小宽度机制参考 [MDN min-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-width)。不为低影响视觉细节增加测试框架或反复追求像素级一致。
