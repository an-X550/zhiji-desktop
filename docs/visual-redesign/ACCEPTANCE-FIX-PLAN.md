## 3. 有限且有效的验收

| 场景 | 验收要求 |
| --- | --- |
| 暗色日志＋超出编辑区的长模板 | 无白色滚动轨道；正文可滚动到底；保存按钮可达；模板仍追加 |
| 项目／模板原生下拉展开 | 普通、选中、禁用文字清晰；手动暗色＋系统浅色以及反向组合正确 |
| 日志与历史模式切换 | 两个入口易识别；实测命中高度；键盘焦点可见；未保存确认仍有效 |
| 历史长中文、连续英文标题与长正文 | 列表和阅读器不相交、不侵入对方；无整页横滚；选中记录能阅读与编辑 |
| 历史两项／三项筛选 | 搜索与项目控件正常分配；紧凑窗口折叠后不遮挡 |
| 首页全屏与恢复窗口，空记录与已有记录 | 内容组均衡；主行动清晰；矮窗口完整可达；不为凑面积新增内容 |
| 其他页面暗色快速回归 | Agent 输入与发送可见；项目／设置表单与弹窗可读 |

覆盖代表 CSS viewport：约 1000×640、1280×800、1536×864；再对实际 14 寸设备最大化／恢复窗口验证。若最小窗口限制不允许某尺寸，以实际可达最小 viewport 记录，不伪造尺寸。复用现有 150% 缩放回归，区分 Windows DPI 与 Electron zoom。

优先补一条有价值的现有 E2E：长记录在双栏和折叠布局中的边界／无横向溢出断言。其他静态样式不新增逐属性测试。运行项目已有 typecheck、lint、相关单测；按照现有交付流程构建并在当前产物验收。上一轮报告中的通过结果不算本轮结果。

原生下拉必须实际展开验证，不只看关闭态截图或 computed style。平台自动化无法捕获时明确保留该项待人工确认，其余工作继续；不得宣称整体通过。修复已发现缺陷后确认一次，必要项通过即停止额外润色。
