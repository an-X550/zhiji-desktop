日期：2026-09-08。状态：用户已认可最终浅色样板，真实桌面端基础实施已完成；v2.6.11 验收修正结果见 [ACCEPTANCE-FIX-IMPLEMENTATION-RESULT.md](ACCEPTANCE-FIX-IMPLEMENTATION-RESULT.md)，AI 恢复与收尾验收见 [RECOVERY-IMPLEMENTATION-RESULT-2026-09-09.md](RECOVERY-IMPLEMENTATION-RESULT-2026-09-09.md)，日志核心体验扩展验收见 [2026-09-09-journal-experience-acceptance.md](../2026-09-09-journal-experience-acceptance.md)，基础交付记录见 [IMPLEMENTATION-RESULT.md](IMPLEMENTATION-RESULT.md)。当前版本核对为 2.6.13。

## 1. 目标与本次范围
在保留原版浅色、简约、柔和感的基础上，落地已认可的文档式日志布局。目标是让写作更自然、控件更克制，而不是追求新旧反差。

**本次完整交付范围：真实日志页 + 必要共享外壳/主题样式 + 已查实的 Agent 缩放裁切和对比度修复。** 其他页面只做共享样式的回归适配，不在本轮重做信息架构。全端推广另列后续阶段，不能自行扩大；也不能把本轮完成误称为全端重设计完成。

唯一当前视觉依据：[交互样板](journal-concept.html)、[浅色](journal-light.png)、[深色](journal-dark.png)、[紧凑](journal-compact.png)、[空白](journal-empty.png)、[宽屏](journal-wide.png)。此前深导航/紫色方案已否定；[旧提案](journal-v1-rejected.png)和上轮旧方案仅作历史参考，不能覆盖本文件。

## 2. 选型：复用优先
| 事项 | 采用 | 原因 |
|---|---|---|
| 前端栈 | 现有 React、TypeScript、CSS variables | 视觉问题不需要迁移框架 |
| 编辑器/控件 | 现有 textarea、日期/项目控件、Button、TemplateManager、原生 dialog | 保留真实交互和已完成的可用性修复 |
| 设计方法 | 本地 impeccable 的 Operate/Read、craft-floor | 围绕已认可样板做细节和状态复核，不再进行主题竞赛 |
| 图标/字体 | 现有 SVG 和 Windows 系统字体回退 | 避免无收益依赖和中文字体加载成本 |
| 新组件库 | 默认不加 | Radix 属于无样式原语，不会自动提升本方案视觉；已有原生能力足够时无需替换 |
| 后端 | 复用已优化实现 | 保留精确证据、审批恢复、写入/维护/IPC 边界；视觉调整不新增接口 |

资源参考：[Impeccable GitHub](https://github.com/pbakaus/impeccable)、[Radix 官方介绍](https://www.radix-ui.com/primitives/docs/overview/introduction)。已在本会话核查，不必重复搜索 stars、批量试装或多轮生成图片；只有明确交互缺陷证明需要时，才核查并采用一个针对性的成熟组件。

## 3. 已认可的视觉要求
- 浅灰绿导航、低饱和选中态；保留中文标签，设置下置，不使用强反差深炭侧栏。
- 一块 14px 圆角、单层轻阴影的写作面；正文不嵌套输入框边框或第二层卡片。
- 日期作为文档标题，星期作辅助信息；年份与“更改日期”在下方，原生日期控件按需展开，避免重复日期。
- 项目/模板是紧凑辅助工具；工具入口可发现、可聚焦、可键盘关闭。
- 正文 16–18px，行高约 1.75，最大约 44em；标题 28–30px。不要缩小正文来满足首屏条件。
- 保存操作属于文档本身；分隔线内收，与正文边缘协调；控件圆角约 7–8px，只有主操作使用实心绿色。
- 周统计/最近记录保持可访问，但不抢占写作首屏；生成的反馈使用独立 Markdown 阅读区。
- 暗色从同一语义 token 派生，不简单反色。细节以样板实际 CSS 为准。

| 角色 | 明色 | 暗色 |
|---|---|---|
| 工作底 | #F7F8F7 | #1D2220 |
| 写作面 | #FFFFFF | #252C28 |
| 导航 | #F0F3F1 | #202722 |
| 主文字 | #262C29 | #EAF0EC |
| 辅助文字 | #616B65 | #B2BFB6 |
| 主动作 | #236C56 | #94CFB1 |
| 主按钮文字 | #FFFFFF | #1B3526 |

样板导航宽约 188px，紧凑 156px；正文面最大 940px。这些是比例参照，不是固定高度合同。移植到 Electron 要按真实可用区域布局，样板顶部 40px 演示栏不进入产品，也不能留下对应空白。

## 4. 视觉与业务的边界
HTML 是视觉参照，不是生产实现源。不得复制合成内容、固定日期、假保存、模拟 AI、顶部演示控制、比较遮罩或样板的浏览器 confirm。
- 日期由现有本地日期工具和 state 派生，不使用 UTC 转换制造日期偏移。
- 模板沿用生产端**追加到已有正文**的行为，不复制样板“替换内容”的演示行为。
- 保存/生成按钮继续消费真实 canGenerate、body、已有今日日志与任务状态；空编辑器不等于一律禁用生成。
- 未配置 AI、补写历史日期只按既有条件保存；不可因为样板展示“保存并生成反馈”就绕过条件。
- 保留保存成功/失败、重复提交保护、反馈生成与结构化失败重试、未保存离开确认、中文输入行为。
- previewToken/approvalId、备份恢复、数据权限及 IPC 来源校验原样有效。

## 5. 验收与止损
视觉验收看轻盈度、边缘一致、正文可读性和操作层级，不要求与旧版差异越大越好。当前样板已获用户认可，执行者不应再要求用户选择风格；需要修正常规实现差异时直接修。

机械验收与实际命令见 [EXECUTION.md](EXECUTION.md)。样板自查见 [self-review.json](self-review.json)，它只证明 HTML 样板，不证明当前 Electron 已完成修复。真实日志页达到样板水平并完成约定验证后停止，交付实际证据；不再进行低收益的反复抛光。

后续可推广到 Agent、历史/项目、复盘设置及开始页，但本轮仅记录方向，不直接实施全端改版。
