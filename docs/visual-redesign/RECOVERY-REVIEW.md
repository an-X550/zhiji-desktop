# v2.6.11 审查与高性价比修正方案

日期：2026-09-09。状态：方案待实施；本轮未改产品代码、未调用真实 AI、未重跑 Electron。证据来自用户七张截图、当前源码、git HEAD 与工作区差异。上一轮测试通过不代表真实模型链路可用。

本文件在首页、品牌说明、日志写作区与 AI 恢复方面取代此前视觉方案；保留已修好的中性暗色、原生控件主题、历史 Grid 和大尺寸模式切换。

## 第一性原理结论

知己的价值是“记录经历 → 看见模式 → 采取行动 → 验证变化”。首要条件是日志可靠保存、AI 能产生有效结果；首页要让功能一眼可辨，写作页要让用户专注输入和完成保存。上轮删掉首页卡片分组降低了识别效率，再调整居中也不能补回这个问题。应复用旧首页，不再创造新首页。

优先顺序：P1 恢复日反馈／周期复盘的可用性；随后恢复旧首页、精简写作页并修复对齐；品牌文案随外壳局部调整完成。AI 根因验证不可省，但不需要回滚全部前后端优化。

## 已确认的问题与可复用内容

### 1. 首页：直接复用旧分组设计

用户第一张图是目标参考。仓库提交 `458f5d7` 的 `apps/zhiji-desktop/src/index.css` 已有对应 `.start-page`、`.start-hero`、`.next-step-card`、`.capability-links` 和 `.start-status`：720px 内容上限，主建议卡片有内边距／表面／边框／圆角，三个快捷入口也有独立卡片；当前 start-page.tsx 的结构仍可直接承接。

局部移回这组样式及必要的字号、间距依赖，用当前主题变量适配明暗色。恢复旧页面的大小、位置和分组关系，而非只给现有宽布局加框。不要整文件 git checkout 或回退全局 token，否则会丢失本轮已修好的布局与主题。旧版表面实现主要是背景、边框与阴影；截图所感知的“毛玻璃”不意味着必须新增昂贵的 blur 或窗口透明效果。

### 2. 品牌说明：说清用户价值

app-shell.tsx 将“本地优先”放进所有非日志页面的 topbar；这是技术属性，不能代替页面标题或产品价值。旧 CSS 已有 `.brand small` 可复用。

采用文案：**记录，分析，行动**。放在左侧“知己”下方，允许两行，保持辅助字号但可读；删除顶栏“本地优先”。顶栏左侧恢复当前页面名称，右侧保留 AI 配置状态。窄侧栏沿用现有折叠方式，不挤压导航。

“数据保存在本机”仍放在侧栏底部；“生成反馈时会发送所选内容到配置的 AI 服务”继续放在生成动作附近。这两项表达实际数据边界，不用品牌口号替代，也不暗示 AI 完全离线。

### 3. 写作页：只保留完成当前记录所需的信息

保留：写日志／过去日志切换；日期；可选项目／模板；正文；保存状态；仅保存／保存并生成；必要的数据发送说明；本次生成进度、结果与失败恢复。

删除写作模式下的“最近记录”与“本周记录／做复盘”整块 `journal-support`，同时删除仅服务该块的派生值与引用。历史记录继续由“过去日志”访问，复盘由导航访问。不要仅用 CSS 隐藏，也不要删除历史模式里的列表。最近记录不是当前写作的必要上下文，现有入口已经覆盖该用途。

### 4. 正文与保存操作：共用内容宽度

`.writing textarea` 有 `max-width:44em`，外层卡片最多 940px；正文内边距 44px，而 footer 使用 28px margin 和单侧 padding。大窗口时文本列先停止增长，按钮仍贴着更宽卡片右缘，形成明显错位。

使用一个共同的写作内容容器／局部宽度变量统管日期、工具、正文、状态与操作栏；正文和操作栏左右边界一致。优先在卡片内约束内容宽度，取消 textarea 独有的额外 max-width；按钮保持内容列右对齐。紧凑窗口统一缩小内边距，不使用绝对定位或 fixed 按钮。保留有用的正文编辑高度，但不因删掉底部列表而把编辑器硬拉满全屏。

另外，截图显示保存后失败时正文消失。源码 `save()` 在保存成功后立即 `setBody('')`，随后才请求 AI：这不证明日志丢失，却使失败恢复缺少上下文。最低成本处理是保存后保留正文，并同步持有返回的 journal id/updatedAt、将草稿标记为已保存；再次保存走 update，不能重复 create。复用已有 editing 与未保存判断，避免另造状态机；新开一篇通过清晰的既有或小型重置动作开始。AI 失败保留正文、关联信息与重试目标；这项需要行为测试，不只是视觉修饰。

## 5. AI 失败：先锁定共享链路，不能猜服务商

### 事实

- 用户补充完整时序：输入有效日志 → 点击保存并生成 → 显示已保存／正在分析且编辑器清空 → 约30秒后失败。不能把清空后的UI截图当作提交时无有效日志，也不能仅凭30秒认定超时。
- GenerateDailyReview.execute 按请求日期从 journals.list() 重新读取已保存日志，再经 buildDailyContext 进入请求；不是读取清空后的 textarea。因此清空是已确认的交互问题，是否存在保存后读不到／日期不匹配／上下文漏正文，要用链路测试验证，不能直接认定它导致空输出。这里 outputLength=0 指模型返回正文，不是输入日志长度。当前 provider 超时配置为60秒，截图的 length 是另一类信号。
- 用户日反馈截图：`empty_content`、`finish_reason=length`、`outputLength=0`。说明这次结构化结果没有可用正文，同时带有长度结束原因；不能归因于 CSS、网络完全不通或 Key 必然无效。
- daily-runtime.ts 使用 1200 tokens；periodic-runtime.ts 为月复盘 2400、其他周期 1800。均经过 collectValidated → collectStructured。
- collectStructured 使用非流式 Chat Completions、`max_tokens` 和 JSON object，读取 message.content；没有像 Agent 路径那样显式处理 DeepSeek thinking 参数。
- collectValidated 先判断空内容，再判断 length；重试只追加格式要求，预算不变。因此长度耗尽可能被归入普通空内容，相同限制下再次失败。
- git HEAD 中日反馈已经是 1200 tokens，不能说这是本次优化新引入的。周期复盘则从旧流式 collect 改成当前有显式上限的结构化路径，这是明确的排查差异，但尚未证明因果。
- 月复盘 UI 直接展示异常 message，出现 Electron IPC 的 `Error invoking remote method` 包装；其具体 finishReason 不能从截图确定。
- 连接测试 `testConnection()` 只确认 HTTP 成功，未验证正文；“AI 已配置”也只是配置状态，均不代表复盘实际可用。

### 关键假设与最小验证

优先验证输出预算耗尽；若实际模型支持推理，还需核对预算是否覆盖推理、是否只产生推理而无最终正文。另有 JSON 模式空输出、上下文上限、兼容服务商参数差异等解释。**当前没有实际服务商／模型与脱敏响应元数据，不能把 DeepSeek 或推理耗尽写成定论。**

对于实际使用 DeepSeek 的情况，可参考官方 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/) 与 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)；后者明确提示可能返回空正文。须对照实际模型与接口能力，不能把一家参数发送给全部 OpenAI-compatible 服务商。

先复用已有 ProviderUsage、StructuredOutputDiagnostics、collectValidated 与 provider 测试：保留 providerId/model、有效 token 预算、结束原因、输入／输出 token 计数，以及是否存在 reasoning/拒答等元数据。不要记录 API Key、请求完整正文、日志或推理内容。长度原因优先分类为 truncated，即使 content 为空也保留真实结束原因。

### 最小修复路径

1. 依据实测模型能力调整结构化请求的输出预算与必要参数，区分最终输出需求和推理预算。可以有限提高预算，但上限由任务和模型能力决定，不能统一给所有请求超大额度。
2. 对 length 类故障只允许一次有区别的恢复（在允许范围内增加输出预算）；无 length 的 JSON/schema 故障保留已有一次格式重试；合计最多两次请求，不叠加重试循环。401/403/429、取消等不走格式重试。
3. 保留 JSON/schema 校验和“有效结果才落盘”。绝不能把 reasoning_content 当报告、空内容写成成功、取消校验，或因复盘失败删除日志。
4. 周期复盘复用现有日反馈错误呈现思路与安全错误工具；如果 IPC 无法保留诊断，使用已有结果类型模式做最小 typed error 返回。用户看到明确失败原因和恢复动作，技术字段折叠显示，不暴露 remote method 包装。
5. 不把旧流式路径直接当永久回退：可用于隔离环境对照请求差异，但仍需保留结束原因、验证与安全落盘。Agent 走独立流式／工具链，不能由日反馈失败推断 Agent 一定坏，也不能因其独立而跳过最小回归。

8/1–9/30 是跨月范围，含尚未到来的日期。它会影响材料与复盘命名，但不能解释短日反馈也出现相同错误。检查现有契约是否允许自定义范围；允许则按真实范围标注且只纳入已有材料，不默默缩成一个月。不要把日期限制作为本次 AI 修复的替代。

## 验收边界

本轮是审查和规划；没有声称 AI 已恢复。后续须用合成材料验证失败→恢复→有效报告落盘，并单独报告真实模型验证结果；模拟接口通过不能代替真实兼容性通过。前端无需再追求额外风格变化，已确认需求通过即停止。
